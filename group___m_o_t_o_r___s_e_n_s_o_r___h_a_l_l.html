Detailed Description

Motor Sensor Hall on RA MCUs. This module implements the Motor sensor Interface.

Overview

The Motor Sensor Hall module provides rotor angle estimation and rotational speed calculation using Hall effect sensors. Hall sensors detect the magnetic field of the rotor and output digital signals that indicate the rotor position. By monitoring the transitions of these Hall signals, the module calculates the electrical angle and speed of the motor.

Features

The Motor Sensor Hall module has the following key features:

  • Rotor electrical angle estimation based on Hall sensor signals (U, V, W)
  • Rotational speed calculation with multiple estimation methods:
    • Moving average speed estimation
    • Last pulse speed estimation
    • Automatic weighted mixing of both methods
  • Rotation direction detection (CW/CCW)
  • Configurable Hall signal pattern for different motor configurations
  • Angle correction coefficient for alignment adjustment
  • Speed output clamping based on elapsed time for stability

Clock Configuration

This module does not require specific clock configuration. The speed calculation is based on the carrier interrupt period provided by the inner control loop.

Pin Configuration

This module requires three GPIO pins configured as inputs for the Hall sensor signals:

Pin Description
Hall U Hall sensor U-phase signal input
Hall V Hall sensor V-phase signal input
Hall W Hall sensor W-phase signal input

Configure these pins as digital inputs in the Pin Configuration tool.

Usage Notes

Hall Sensor Signal Pattern

The Hall sensor signal pattern must be configured according to the motor and sensor arrangement. The pattern array defines the sequence of Hall signal combinations (3-bit value from U, V, W signals) for one electrical revolution. The pattern should include 6 unique values plus a wrap-around value.

Example pattern for a typical BLDC motor: {5, 4, 6, 2, 3, 1, 5} // Pattern wraps from index 6 back to index 0

Speed Estimation Methods

The module supports three speed estimation methods selectable via the speed_select configuration:

Method Description Use Case
MOTOR_SENSOR_HALL_SPEED_SELECT_AUTO Weighted average of both methods General purpose (recommended)
MOTOR_SENSOR_HALL_SPEED_SELECT_MOVAVG Moving average over 6 Hall periods Smooth speed output, higher latency
MOTOR_SENSOR_HALL_SPEED_SELECT_LAST_PULSE Speed from latest Hall period Fast response, more noise

When using automatic mode, the weight between fast and precise estimation is dynamically calculated based on:

  • Absolute speed (lower speeds favor precise estimation)
  • Deviation between the two estimates (larger deviation favors fast estimation)

Angle Correction

The angle_correct parameter allows adjustment of the estimated angle to compensate for:

  • Hall sensor mounting offset
  • Motor phase alignment
  • System-specific calibration

The correction value is added to the calculated angle in radians.

Speed Clamping at Low Speed

When the time elapsed since the last Hall signal transition exceeds the maximum_period count, the estimated speed is automatically set to zero. This prevents erroneous speed readings when the motor is stationary or rotating very slowly.

Integration with Motor Control Loop

The Motor Sensor Hall module is designed to work with the motor control inner loop:

  1. Call RM_MOTOR_SENSOR_HALL_Open to initialize the module
  2. Call RM_MOTOR_SENSOR_HALL_AngleSpeedInit to set up data exchange pointers
  3. Call RM_MOTOR_SENSOR_HALL_AngleSpeedCalc periodically from the carrier interrupt to update angle and speed
  4. Call RM_MOTOR_SENSOR_HALL_PositionSpeedGet to retrieve mechanical position and speed
  5. Call RM_MOTOR_SENSOR_HALL_Close to finalize the module when done

Limitations

Developers should be aware of the following limitations when using the Motor Sensor Hall module:

  • The module requires a minimum rotational speed for accurate speed estimation. At very low speeds, the estimation accuracy decreases due to the discrete nature of Hall sensor signals.
  • The angular resolution is limited to 60 electrical degrees (π/3 rad) between Hall signal transitions. Interpolation is used between transitions, but accuracy depends on speed consistency.
  • Direction detection requires at least one Hall signal transition. Initial direction after startup may be incorrect until the first transition occurs.
  • The maximum_period should be set appropriately for the application's minimum expected speed to avoid premature zero-speed detection.
  • Only the functions/types/macros exposed via rm_motor_sensor_hall.h and rm_motor_sesnor_api.h should be accessed by user code and that the contents of the other headers is subject to change.

Examples

Motor Sensor Hall Basic Example

This is a basic example of minimal use of the Motor Sensor Hall module in an application.

void rm_motor_sensor_hall_basic_example (void)
{
fsp_err_t err = FSP_SUCCESS;
/* Initializes the module. */
err = RM_MOTOR_SENSOR_HALL_Open(&g_motor_sensor_hall_ctrl, &g_motor_sensor_hall_cfg);
/* Handle any errors. This function should be defined by the user. */
assert(FSP_SUCCESS == err);
/* Reset the module variables. */
err = RM_MOTOR_SENSOR_HALL_Reset(&g_motor_sensor_hall_ctrl);
assert(FSP_SUCCESS == err);
/* Close the module. */
err = RM_MOTOR_SENSOR_HALL_Close(&g_motor_sensor_hall_ctrl);
assert(FSP_SUCCESS == err);
}

Motor Sensor Hall Advanced Example

This example demonstrates using data exchange pointers and angle/speed calculation in a control loop.

/* Pointers for angle and speed data exchange */
static float * gp_speed_el;
static float * gp_angle_el;
static motor_sensor_output_t * gp_sensor_output;
void rm_motor_sensor_hall_advanced_example (void)
{
fsp_err_t err = FSP_SUCCESS;
/* Open the Motor Sensor Hall module */
err = RM_MOTOR_SENSOR_HALL_Open(&g_motor_sensor_hall_ctrl, &g_motor_sensor_hall_cfg);
/* Handle any errors. This function should be defined by the user. */
assert(FSP_SUCCESS == err);
/* Set up data exchange pointers with inner loop */
motor_shared_inner_to_position_speed_t inner_data;
inner_data.inner_control_period = 0.0001f; /* 100us control period */
inner_data.outer_control_period = 0.001f; /* 1ms outer loop period */
err = RM_MOTOR_SENSOR_HALL_AngleSpeedInit(&g_motor_sensor_hall_ctrl,
&gp_speed_el,
&gp_angle_el,
&gp_sensor_output,
(motor_sensor_input_inner_t *) &inner_data);
assert(FSP_SUCCESS == err);
/* Main control loop - typically called from carrier interrupt */
while (true)
{
/* Application work here. */
/* Calculate angle and speed from Hall sensor signals */
motor_sensor_input_inner_t inner_input;
motor_sensor_input_outer_t outer_input;
err = RM_MOTOR_SENSOR_HALL_AngleSpeedCalc(&g_motor_sensor_hall_ctrl, &inner_input, &outer_input);
assert(FSP_SUCCESS == err);
/* Access estimated values through pointers */
float current_speed_el = *gp_speed_el; /* Electrical speed [rad/s] */
float current_angle_el = *gp_angle_el; /* Electrical angle [rad] */
/* Use angle and speed for motor control... */
(void) current_speed_el;
(void) current_angle_el;
/* Get mechanical position and speed */
float mechanical_position;
float mechanical_speed;
err = RM_MOTOR_SENSOR_HALL_PositionSpeedGet(&g_motor_sensor_hall_ctrl, &mechanical_position, &mechanical_speed);
assert(FSP_SUCCESS == err);
/* mechanical_speed is in [rad/s mech] */
/* mechanical_position is in [rad mech] */
(void) mechanical_position;
(void) mechanical_speed;
}
}

Get mechanical position and speed from Hall sensor measurements.

This function retrieves the current mechanical rotational position and speed from the Hall sensor controller. The speed output is normalized to mechanical units [rad/s mech] by dividing the electrical speed by the number of pole pairs. The position output is currently set to zero and must be implemented.

Example:

/* Get mechanical position and speed */
float mechanical_position;
float mechanical_speed;
err = RM_MOTOR_SENSOR_HALL_PositionSpeedGet(&g_motor_sensor_hall_ctrl, &mechanical_position, &mechanical_speed);
assert(FSP_SUCCESS == err);
Parameters
[in]p_ctrlPointer to the Hall sensor instance control structure.
[out]p_posPointer to store the resulting mechanical position [rad mech].
[out]p_speedPointer to store the resulting mechanical speed [rad/s mech].

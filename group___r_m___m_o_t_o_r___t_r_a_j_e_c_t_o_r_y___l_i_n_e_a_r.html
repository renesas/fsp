Detailed Description

Motor Trajectory Linear on RA MCUs. This module implements the Motor Trajectory Interface.

Overview

The Motor Trajectory Linear module provides linear trajectory generation for motor control applications. It calculates smooth reference values that transition linearly from the current position/speed to a target value at a specified slew rate.

Features

The Motor Trajectory Linear module has the following key features:

  • Linear trajectory generation with configurable slew rate
  • Command queuing support (one command can be queued while another is in progress)
  • Immediate command execution with the IMMEDIATE flag
  • Bypass mode for direct reference value pass-through
  • Force alignment support for synchronization
  • Direction (CW/CCW) and acceleration/deceleration state tracking
  • User callback notification when trajectory completes

Trajectory States

The trajectory module operates in the following states:

State Description
TRAJECTORY_STATE_IDLE No trajectory is active. Ready to accept new commands.
TRAJECTORY_STATE_IN_PROGRESS A trajectory is currently being executed.
TRAJECTORY_STATE_QUEUED A trajectory is in progress and another command is queued.

Command Status

When setting a target, the following status values indicate how the command was processed:

Status Description
MOTOR_TRAJECTORY_CMD_ACCEPTED_IMMEDIATE Command was accepted and started immediately.
MOTOR_TRAJECTORY_CMD_QUEUED Command was queued (will execute after current trajectory completes).
MOTOR_TRAJECTORY_CMD_REJECTED Command was rejected (queue is full or invalid parameters).

Usage Notes

Callback Function

The trajectory module requires periodic callback invocations from the motor control algorithm layer. The callback function RM_MOTOR_TRAJECTORY_LINEAR_Callback should be called at regular intervals (matching the configured cycle time) to:

  • Calculate the next reference value based on the current trajectory
  • Update direction and acceleration/deceleration states
  • Handle trajectory completion and queued command transitions

Trajectory Parameters

Linear trajectory parameters are defined using the motor_trajectory_linear_params_t structure. The helper macro MOTOR_TRAJECTORY_LINEAR_PARAMS_INIT can be used for convenient initialization: 

motor_trajectory_linear_params_t linear_params = MOTOR_TRAJECTORY_LINEAR_PARAMS_INIT(100.0F, 10.0F);

Where:

  • First parameter: Target value (e.g., target speed in RPM or target position)
  • Second parameter: Slew rate (rate of change per second)

Immediate Command Execution

To execute a command immediately (aborting any current trajectory and clearing the queue), set the IMMEDIATE flag in the command_flags: 

motor_trajectory_linear_params_t linear_params = MOTOR_TRAJECTORY_LINEAR_PARAMS_INIT(100.0F, 10.0F);
linear_params.base.command_flags = MOTOR_TRAJECTORY_COMMAND_STATUS_FLAG_IMMEDIATE;

Bypass Mode

Bypass mode can be enabled to pass the current reference value through without trajectory calculation. This is useful when:

  • Direct control of the reference value is needed
  • The trajectory module should be temporarily disabled

Enable bypass mode using RM_MOTOR_TRAJECTORY_LINEAR_BypassModeSet : 

err = RM_MOTOR_TRAJECTORY_LINEAR_BypassModeSet(&g_motor_trajectory_ctrl, true);

Limitations

Developers should be aware of the following limitations when using the Motor Trajectory Linear module:

  • Only one command can be queued at a time. If a command is already queued, subsequent commands will be rejected until the queue is cleared.
  • The trajectory calculation assumes a constant cycle time. Variations in callback timing may affect trajectory accuracy.
  • The module uses single-precision floating-point arithmetic.

Examples

Basic Example

This is a basic example of minimal use of the motor trajectory linear in an application.

void rm_motor_trajectory_basic_example (void)
{
fsp_err_t err = FSP_SUCCESS;
/* Initializes the module. */
err = RM_MOTOR_TRAJECTORY_LINEAR_Open(&g_motor_trajectory_ctrl, &g_motor_trajectory_cfg);
/* Handle any errors. This function should be defined by the user. */
handle_error(err);
/* Close the module. */
err = RM_MOTOR_TRAJECTORY_LINEAR_Close(&g_motor_trajectory_ctrl);
handle_error(err);
}

Advanced Example

This example demonstrates setting targets, getting status, resetting, and configuring bypass mode.

void rm_motor_trajectory_advanced_example (void)
{
fsp_err_t err = FSP_SUCCESS;
motor_trajectory_state_t state;
motor_trajectory_command_status_t cmd_status;
/* Open the module. */
err = RM_MOTOR_TRAJECTORY_LINEAR_Open(&g_motor_trajectory_ctrl, &g_motor_trajectory_cfg);
handle_error(err);
/* Set target using linear trajectory parameters */
motor_trajectory_linear_params_t linear_params = MOTOR_TRAJECTORY_LINEAR_PARAMS_INIT(100.0F, 10.0F);
motor_trajectory_target_t target =
{
.p_params = (motor_trajectory_params_base_t const *) &linear_params,
};
err = RM_MOTOR_TRAJECTORY_LINEAR_TargetSet(&g_motor_trajectory_ctrl, &target, &cmd_status);
handle_error(err);
/* Get the current trajectory state. */
err = RM_MOTOR_TRAJECTORY_LINEAR_StatusGet(&g_motor_trajectory_ctrl, &state);
handle_error(err);
/* Reset the trajectory module. */
err = RM_MOTOR_TRAJECTORY_LINEAR_Reset(&g_motor_trajectory_ctrl);
handle_error(err);
/* Set bypass mode. */
err = RM_MOTOR_TRAJECTORY_LINEAR_BypassModeSet(&g_motor_trajectory_ctrl, true);
handle_error(err);
/* Close the module. */
err = RM_MOTOR_TRAJECTORY_LINEAR_Close(&g_motor_trajectory_ctrl);
handle_error(err);
}

Callback Integration Example

This example shows how to integrate the trajectory callback with a motor control loop:

/* Motor control periodic interrupt handler */
void motor_control_isr (void)
{
fsp_err_t err;
float reference_value = 0.0F;
motor_trajectory_callback_args_t args =
{
.p_reference = &reference_value,
.force_align = false,
.align_value = 0.0F,
};
/* Call trajectory callback to get next reference value */
err = RM_MOTOR_TRAJECTORY_LINEAR_Callback(&g_motor_trajectory_ctrl, &args);
if (FSP_SUCCESS == err)
{
/* Use reference_value for motor control */
set_motor_speed_reference(reference_value);
}
}

Queued Command Example

This example demonstrates command queuing behavior:

void trajectory_queued_command_example (void)
{
fsp_err_t err;
motor_trajectory_command_status_t cmd_status;
/* First command - will be accepted immediately */
motor_trajectory_linear_params_t first_target = MOTOR_TRAJECTORY_LINEAR_PARAMS_INIT(100.0F, 10.0F);
motor_trajectory_target_t target1 =
{
.p_params = (motor_trajectory_params_base_t const *) &first_target,
};
err = RM_MOTOR_TRAJECTORY_LINEAR_TargetSet(&g_motor_trajectory_ctrl, &target1, &cmd_status);
/* cmd_status will be MOTOR_TRAJECTORY_COMMAND_STATUS_ACCEPTED_IMMEDIATE */
/* Second command - will be queued */
motor_trajectory_linear_params_t second_target = MOTOR_TRAJECTORY_LINEAR_PARAMS_INIT(200.0F, 20.0F);
motor_trajectory_target_t target2 =
{
.p_params = (motor_trajectory_params_base_t const *) &second_target,
};
err = RM_MOTOR_TRAJECTORY_LINEAR_TargetSet(&g_motor_trajectory_ctrl, &target2, &cmd_status);
/* cmd_status will be MOTOR_TRAJECTORY_COMMAND_STATUS_QUEUED */
/* Third command - will be rejected (queue full) */
motor_trajectory_linear_params_t third_target = MOTOR_TRAJECTORY_LINEAR_PARAMS_INIT(300.0F, 30.0F);
motor_trajectory_target_t target3 =
{
.p_params = (motor_trajectory_params_base_t const *) &third_target,
};
err = RM_MOTOR_TRAJECTORY_LINEAR_TargetSet(&g_motor_trajectory_ctrl, &target3, &cmd_status);
/* cmd_status will be MOTOR_TRAJECTORY_COMMAND_STATUS_REJECTED */
}
